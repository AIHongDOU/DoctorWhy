## 二、硬伤（先打脸，再谈优点）

### 硬伤 1：你装的不是完整版，是"残血版"
本地目录只有 `SKILL.md` 一个文件，而官方仓库的核心资产 `references/`（9 个规则库文件）**一个都没装进来**。SKILL.md 反复声称"9 类 90 条暗规则"，但你的本地环境里这 90 条**一条都不存在**。护城河没运到前线，等于士兵手里只有空枪。

### 硬伤 2：仓库内有两个 SKILL.md，且已分叉
- **根目录 SKILL.md**（本地装的这版）：四阶段流程，`9类90条` 只内嵌 9 条，**全篇没提 references/ 延迟加载**。也就是说，即使你装全了规则库，这个版本也不会去读它们。
- **skills/doctorwhy/SKILL.md**（v3.0.0 打包版）：改成了 Phase 1-5 状态机 + 延迟加载，但它自己的规则索引**只列了 8 个文件，漏了 `rules-specimen.md`**（标本规则永远不会被加载）。

同一个项目两个版本、两套流程、还互相打架——维护半年后必漂移。这是"自用脚本"级的管理，不是"可发布 Skill"级的。

### 硬伤 3：数字自相矛盾
- SKILL.md 说"9 类 **90** 条"，打包版延迟加载说明里写"**80** 条全塞上下文会烧 token"——90 还是 80？
- 根版说"以下是从规则库提取的硬性约束"，实际内嵌 9 条，剩下 81 条要靠宿主 AI"自主发现"去读 references/，而流程里没有任何一句"去读 references/"的指令。**这 81 条是死代码。**

### 硬伤 4：评测是"自嗨满分"，不可信
`evaluation/cases.md` 里 5 个用例全部标了 **15/15 满分**，评测人即作者本人，日期集中在一天，且：
- **无基线对照**：没跑"不带 SKILL 的通用模型 vs 带 SKILL"的对比，无法证明这 90 条规则真的让输出变好了，还是只是自我感觉良好；
- **无盲测/双盲**：作者自己知道期望答案，打勾自然全中；
- **收敛/深度两项纯人工打分**，无评分人一致性；
- 没有"失败案例回归"——最该测的"AI 直接出诊断报告"这种红线用例，恰恰最容易在换了模型后失守。

自评满分 = 测评报告里最刺眼的一个数字。评估工具 `eval_score.py` 本身是加分项，但用成了自我表扬的工具。

### 硬伤 5：触发/分发的工程细节不合格
- **description 太短且无触发词**：`description` 只有一句话，没带"医疗/扫描/影像/细胞/显微镜/LIS"这类触发关键词，`allowed-tools` 是空。在 Trae/Claude 里自动触发率会很低，用户得手动 `帮我问清楚` 才进得来。
- 而触发不了 = 写得再好也没人用到，这是最致命的分发问题。

## 三、竞品横向对比

| 维度 | **DoctorWhy** | **Superpowers / brainstorming**（11w+ star） | **feature:interviewer**（社区 gist） | **hs-req-facilitator**（苏州核朔） | **demand-mining**（CSDN 需求挖掘） |
|---|---|---|---|---|---|
| 定位 | 医疗软件需求追问 | 通用软件工程全流程 | 通用特性需求访谈 | 通用 5 阶段需求分析 | 市场/机会挖掘（非编码需求） |
| 领域知识 | **医疗暗规则（法规级）——唯一** | 无（纯工程） | 无（纯提问技巧） | 无 | 无 |
| 提问方式 | 批量编号开放式问题 | 苏格拉底式提问 | **AskUserQuestion 封闭选项 + 逃生门** | 5 阶段流程 | 信号采集+评分 |
| 安全红线 | 有（拒绝产违规医疗方案） | 无 | 无 | 无 | 无 |
| 上下文管理 | 有（决策登记表+持久化） | 有（plans/spec） | 有（.planning/ 契约） | 有 | 有 |
| 评测 | 有工具但自评满分 | 社区海量实战反馈 | 无 | 无 | 有评分算法 |
| 生态/规模 | 新项目 | **Anthropic 官方市场、23w 安装** | 社区 gist | 小公司项目 | 博客教程 |
| 可安装性 | 残血版，双版本分叉 | 一键安装，跨平台 | 单文件 | cp 即用 | 单文件 |

**对比结论**：
1. **DoctorWhy 在"医疗领域 + 安全红线"上是独一份**——没有任何一个竞品知道"AI 出报告要人工复核""质控不过不能发报告""审计日志不可篡改（21 CFR Part 11）"。这是它值得存在的理由。
2. **但提问体验被 feature:interviewer 甩开**。竞品用 AskUserQuestion 给 2-3 个互斥选项 + 一个"Out of scope"逃生门，把选择压力给到模型、把判断压力卸给用户；DoctorWhy 的追问七原则虽然禁止"整体方案是什么"这种大问题，但多数问题仍是开放式（"多久用一次？""卡在哪？"），把认知负担又推回给用户。
3. **流程管理被 Superpowers 甩开**。Superpowers 有完整的 brainstorm→plan→execute→TDD→review 闭环，DoctorWhy 只覆盖"问清楚"这一环，且没有和后续编码流程咬合。

## 四、值得肯定的部分（别因为上面骂就全盘否定）

1. **医疗暗规则库是真实的护城河**。抽查 `rules-regulatory.md` 和 `rules-clinical-validation.md`：CLSI EP12-A2、STARD、ISO 15189 §5.6、IEC 62304、21 CFR Part 11、NMPA 分类——**引用是真实且大体准确的**，不是编出来的法规。敏感性/特异性 vs accuracy、假阴性不对称、PPV 依赖患病率（Bayes）这些点，是通用模型 90% 会栽的地方，这份库抓得准。
2. **"点破隐含矛盾"的机制设计得好**。每条规则都带"能点破什么矛盾"示例（如"审计日志管理员能清→Part 11 审计不可篡改"），这是把领域知识**翻译成可执行动作**，不是罗列条文。同类 skill 里少见。
3. **收敛即停，不无限追问**。这是和"为了问而问"的伪需求分析器最大的区别，追问七原则+入口分流（明确指令直接执行）都指向"问够就动手"。
4. **决策登记表 + 持久化**。防重复问、防自相矛盾、断会话可恢复——这是长对话质量的工程解法。
5. **红线伦理立场正确**："宁可拒绝，不可出可能伤人的东西"——在医疗场景，这个默认值是对的。

## 五、升级建议（按优先级）

**P0（不修就没人用）**
1. **统一 SKILL.md**：删除仓库根目录版本，只保留 skills/doctorwhy/ 打包版，并补上缺失的 `rules-specimen.md` 索引；修正 80/90 数字。
2. **强制规则库加载**：在 SKILL.md 里写死"进入 Phase 3 前必须读对应 `references/rules-*.md`"，不能靠 AI 自觉。
3. **修 description 与触发**：加触发关键词（医疗/影像/显微镜/细胞/扫描/LIS/质控/标本），`allowed-tools` 至少给 `Read, Grep, WebSearch`（它要读规则库、查法规）。
4. **本地补装 references/**：把 9 个规则文件装进项目，否则你手上的版本就是空壳。

**P1（不修会被竞品碾压）**
5. **引入封闭式选项提问**：向 feature:interviewer 学习，关键决策用"A/B/C + 逃生门"，减少开放式问题。
6. **砍掉/收敛 UI/登录越界**：UI 设计有 frontend-design 这类强竞品，DoctorWhy 的 UI 问题库毫无差异——聚焦"影像/检验/器械/LIS"这类有暗规则的品类，把 UI 部分削到只剩医疗特有约束（高对比、隔距读屏、合规提示）。
7. **重建可信评测**：加"无 SKILL 基线"对照组，跑至少 1 个红线失败用例的回归，用第二人盲评替代自评，别再给 15/15。

**P2（自用转发布）**
8. 明示能力边界：这是"提示词级红线"，不是合规保障——在 README 声明"本 skill 的拒绝/合规建议不构成法律意见，仅供需求分析"。
9. 多模型验证（Claude/GLM/豆包），发布 CI 校验规则文件存在性。

## 六、一句话总结

> **DoctorWhy 是"医者"——但它把手术刀装进了一个漏底的盒子：医疗暗规则是真的救命，可规则库没装、版本在分叉、评测在自嗨。先把盒子补好，再谈救人。**
