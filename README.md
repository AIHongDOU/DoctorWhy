# med-req-prober · 医疗需求追问器

> 说不清医疗需求?它帮你一步一步问清楚,然后直接产出能跑的代码。

[![Claude Skill](https://img.shields.io/badge/Claude-Skill-4A90D9)](https://claude.ai) [![License](https://img.shields.io/badge/license-MIT-green)](LICENSE)

**一句话**:面向想开发医疗软件、却说不太清需求的开发者 —— 用一轮接一轮的小问题,把模糊想法翻译成**可执行的技术方案 + 可运行的代码**。

它不懂医疗的开发者的**需求翻译层**:你描述手段,它问出目标;你掉进医学/硬件的坑,它用大白话告诉你;你确认完,它直接把方案写成代码。

---

## 为什么需要它

你说过这样的话吗?

> "我要在 20x 扫描时加模型识别,存细胞坐标转真实物理坐标到缓存库,选区时一瞬间知道区域细胞构成 —— **这种需求不好描述。**"

问题不在你,而在:**你用"技术步骤"描述需求,而通用 AI 缺医疗/硬件领域知识,无法帮你补全隐含约束。**

med-req-prober 解决的就是这件事 —— **把"我说不清"变成"我能答"**。

---

## 它是怎么工作的

一个模糊的医疗需求进来,它用追问把它变成清晰的方案 —— 三步,像讲故事一样:

<p align="center">
  <img src="docs/images/story-1-confused.png" width="30%" alt="第一步:说不清需求"/>
  <img src="docs/images/story-2-probing.png" width="30%" alt="第二步:AI 追问"/>
  <img src="docs/images/story-3-clear.png" width="30%" alt="第三步:变清晰"/>
</p>

| 第一步 · 说不清 | 第二步 · 被追问 | 第三步 · 变清晰 |
|---|---|---|
| 开发者抓耳挠腮:需求讲不明白 | AI 一步一步问小问题,帮你把想法说出来 | 茅塞顿开,直接产出方案和代码 |

```
┌─────────────────────────────────────────────────────────┐
│ 开发者:一个模糊的医疗需求(说不清 / 一瞬间 / 大概)          │
└─────────────────────────────────────────────────────────┘
                        │
                        ▼
┌─────────────────────────────────────────────────────────┐
│ 追问引擎:                                              │
│   ① 复述理解,确认对齐                                    │
│   ② 按框架维度走(目标→用户→主流程→数据→边界→交付)         │
│   ③ 抓隐含矛盾并点破(领域知识)                           │
│   ④ 注入领域现实(技术约束,大白话讲)                      │
│   ⑤ 能画完整数据流 → 收敛                                │
└─────────────────────────────────────────────────────────┘
                        │
                        ▼
┌─────────────────────────────────────────────────────────┐
│ 输出:                                                  │
│   1. 数据流图                                            │
│   2. 追问总结(拆出的真实目标 + 已定决策)                  │
│   3. 待确认清单                                          │
│   4. 可运行代码(UI → HTML / 逻辑 → 接口骨架)             │
└─────────────────────────────────────────────────────────┘
```

### 它追问的样子

```
开发者:我想优化登录界面,目前界面太普通不美观。

→ ① 这个登录界面是谁在用?
→ ② 现在"太普通"具体是哪不满意?
→ ③ 登录界面要显示哪些信息?(产品名/型号/版本号/合规提示)

开发者:值班技师在用,想要重新设计一版,产品号需要显示。

→ ④ 技师是"天天登录"还是"开机一次就挂着"?
→ ⑤ 将来要支持医院工牌扫码/刷卡登录吗?

开发者:开机登录一直保持;要预留扫码。

→ 输出:一版深色医疗质感登录界面(可直接跑 HTML)+ 设计说明
```

### 它的核心资产:规则 + 框架,而不是问题库

- **7 条核心规则**:小粒度提问、具体到界面/操作、一次一个、大白话、按优先级、拆目标、收敛就停。
- **提问框架**:通用(目标→用户→主流程→数据→边界→交付)+ 扫描/影像 + UI/登录。
- **5 个推进动作**:复述对齐 / 按维度走 / 抓矛盾 / 注入现实 / 收敛。

**框架是"往哪问",动作是"怎么问"。** 它不靠堆问题碰运气,而是接住任何需求。

## 安装

将本仓库作为 Claude skill 使用:

```
# 克隆到你的 skills 目录
git clone https://github.com/<你的用户名>/med-req-prober.git
```

在对话中触发:

- **手动**:说"用 med-req-prober 帮我问清楚这个需求"
- **自动**:检测到医疗/扫描/影像/检测需求 + 模糊词(说不清/一瞬间/大概)时自动进入

## 已验证的实弹场景

| 场景 | 需求 | 产物 |
|---|---|---|
| 100X 细胞分类 | "100X扫描时分类细胞类别" | 追问→数据流→40分类方案 |
| 玻片拼接 | "把20x图片拼成玻片系统" | 重叠区对齐 + 坐标映射 demo(自检通过) |
| 登录界面 | "登录界面太普通不美观" | 医疗质感登录界面 HTML(可跑) |

每一个场景都用**规则驱动**完成 —— 不是靠查问题库,而是按框架现场生成小问题。
