# 暗规则库 · 硬件约束(Hardware Constraints)

> 医疗设备软件必须服从的硬件现实。通用 AI 完全空白:它不知道 100x 油镜为什么慢、为什么必须先低倍识别、为什么像素坐标要换算成物理坐标。
> 这些约束直接反推软件设计 —— 理解硬件,软件才不会设计出跑不动/对不上的功能。
> 每条 = 规则 + 为什么(硬件现实)+ 踩过什么坑。

---

## 1. 低倍先于高倍,是物理顺序不是偏好

- **规则**:扫描流程必须低倍(20x)先扫整片,再高倍(100x)按选区精细扫。不能跳过低倍直接高倍。
- **为什么**:100x 视野极小、拍照慢,不可能全片扫。必须先低倍看清全貌、选出关键区域,高倍才去精扫。
- **踩坑**:设计成"100x 直接全片扫" —— 物理上几小时一张,或者根本扫不完;或没低倍选区的底图,高倍不知去哪扫。

## 2. 像素坐标 → 物理坐标:必须建立换算基准

- **规则**:图像里的位置(像素)要换算成载物台的物理坐标(微米/毫米),才能控制电机去那个位置拍照。换算需要标定:每像素多少微米、原点在哪、X/Y 轴方向。
- **为什么**:软件在图上框选,硬件要移到真实位置。没有换算基准,图上的"那一点"物理上找不到。
- **踩坑**:只在像素坐标里操作,选区框了但油镜去不了正确位置;或没标定,图上 1px 和物理 1µm 对不上。

## 3. 标定需要标尺片,不是拍脑袋

- **规则**:像素→物理换算要用已知尺寸的标尺片/网格片实测得到,不能假定。标定参数要记录、可校准。
- **为什么**:光学放大倍数有实际误差,物镜/相机组合的真实像素尺寸要实测才准。
- **踩坑**:用厂家标称倍数算像素尺寸,实际偏差 5%,100x 下错开几个细胞视野。

## 4. 平台有机械误差(漂移),软件要容忍

- **规则**:电机平台移动到"理论位置"和"实际位置"有微小偏差(背隙、振动、累积误差)。软件不能假设"电机说在哪就在哪",要有对齐/校正手段。
- **为什么**:机械精度有限,长时间/长行程移动后位置漂移。图像拼接、选区定位都要抗漂移。
- **踩坑**:拼接图靠坐标硬拼,平台一漂,细胞错开/重影(见 MC-01:需重叠区对齐)。

## 5. 100x 油镜:慢 + 图大 + 对焦难,软件要异步

- **规则**:高倍拍照慢(曝光/对焦/移动)、单张图大。软件不能阻塞式等每张高倍图处理完,要异步流水线:拍→处理→存分开。
- **为什么**:100x 一张图动辄几十 MB、要逐点对焦,几十分钟扫一片。阻塞式等待会让整个流程卡死。
- **踩坑**:把推理挂在拍照流水线上阻塞扫描;或整张几十亿像素拼接图直接存内存(爆内存,需金字塔切片)。

## 6. 对焦是硬问题:焦平面不是平的

- **规则**:玻片样本表面有起伏,不是完全平面。自动对焦要逐区域找焦(如 12 点定位法),不能假设"对一次焦全片清晰"。
- **为什么**:高倍下景深极浅,样本起伏 1µm 就可能失焦。必须分区定焦。
- **踩坑**:全片一次对焦,边缘区域全模糊;或没定焦流程,高倍全糊。

## 7. 滴油/浸油:高倍成像的前提,有物理顺序

- **规则**:100x 油镜需要浸油(滴油→涂抹→扫油镜),软件流程要安排滴油节点,并处理油的状态(干了、少了)。
- **为什么**:油镜的数值孔径(NA)依赖浸油,没油就是普通干镜,分辨率上不去。这是物镜物理特性。
- **踩坑**:流程里没有滴油步骤,100x 拍出来全糊;或没检测油量,中途没油还在拍。

## 8. 相机视野/分辨率:决定"一屏能看到多少"

- **规则**:不同倍率下相机视野和单细胞像素数不同。软件要按倍率管理视野(轮廓相机看全片、主相机看细胞),不能混用。
- **为什么**:轮廓相机广视野看整片,主相机高分辨率看细胞,两套成像系统各有分工。
- **踩坑**:用高倍相机扫全片(慢死);或用轮廓相机看细胞(看不清)。

## 9. 硬件状态要反馈给软件:自检/状态上报

- **规则**:软件要读取硬件状态(平台位置、物镜位置、自检结果、相机连接),在 UI 显示(见 rules-device-ui 的状态区),异常时告警。
- **为什么**:软件不知道硬件在干嘛,就不知道流程进行到哪、有没有故障。
- **踩坑**:开机自检结果不反馈到软件,电机卡住软件还继续扫;或硬件状态只在硬件层,UI 全黑。

## 10. 流程设计要以"硬件能做什么"为边界

- **规则**:扫描流程的每个步骤都要问"硬件此刻能不能做"——位置到没到、对好焦没、油滴好没。硬件没就绪,软件不能往下走。
- **为什么**:软件快于硬件 = 空转/拍错。流程要按硬件就绪状态推进,不是按软件逻辑推进。
- **踩坑**:软件以为"移动完成了"就拍照,其实平台还在动,拍出来全糊。

## 这些规则能点破什么矛盾(供"点破隐含矛盾"动作使用)

- 用户说"100x 直接全片扫描,不用低倍" → 点破"省步骤" 与 "高倍视野小/慢,必须先低倍选区" 的矛盾:物理上跑不完。
- 用户说"图上框了就直接用像素坐标控制电机" → 点破"简单" 与 "像素↔物理需标定换算" 的矛盾:电机找错位置。
- 用户说"拼接图直接整张存内存,方便放大" → 点破"方便" 与 "几十亿像素爆内存,需金字塔切片" 的矛盾(见 MC-01)。
- 用户说"对一次焦就全片扫" → 点破"省时" 与 "样本起伏/景深浅需分区定焦" 的矛盾:边缘全糊。
