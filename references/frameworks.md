# 提问框架(展开版)

框架是"维度",问题库是"例子"。每次追问按框架的维度走,结合当前需求现场生成具体小问题。

## 通用框架

| 维度 | 要问清什么 | 例子 |
|---|---|---|
| 目标 | 真正要达成什么(用户说的常是手段) | "20x加模型识别+存坐标+缓存"→ 真正目标"选区时一瞬间知道区域构成" |
| 用户/场景 | 谁用、什么环境、多久用一次 | 值班技师要快,开机操作员可以慢 |
| 主流程 | 核心动作从哪到哪 | 扫描:轮廓→低倍→选区→滴油→油镜 |
| 数据 | 产生什么、存哪、谁读写、怎么换算 | 细胞坐标→物理坐标→缓存库→选区查询 |
| 边界 | 异常/失败/中止怎么办 | 识别失败、扫描中止、低置信度 |
| 交付 | 结果给谁看、怎么呈现 | 报告给医生、AI计数 vs 医生改判 |

## 扫描/影像类框架

- **识别时机**:边拍边分 / 拍完再分 → 决定性能约束
- **分类粒度**:粗分类(有核/巨核)/ 细分类(40分类骨髓学)→ 决定模型难度
- **结果展示**:位置 / 弹窗 / 统计触发 → 决定交互
- **坐标与缓存**:换算基准 / 原始 vs 确认结果 → 决定存储
- **报告与改判**:两栏 / 以医生为准 / 是否回写 → 决定数据流与合规

## UI/登录类框架

- **使用场景与频率**:值班技师 / 开机操作员 / 一天几次
- **信息层级**:产品名 / 型号 / 版本号 / 合规提示
- **视觉方向**:深色医疗质感 / 亮色现代
- **交互约束**:触控大屏 / 隔距读屏 / 色盲弱光
- **预留扩展**:扫码 / 刷卡 / 多语言

## 医疗软件特有的"暗规则"(追问时会主动带出)

- 医疗器械 UI:高对比、大字号、警示不能只靠颜色(红绿色盲)、数据密集布局
- 数据安全:PHI 脱敏、日志不能存患者名、审计追踪
- 硬件约束:油镜拍照慢/图大、平台位移有误差(漂移)
