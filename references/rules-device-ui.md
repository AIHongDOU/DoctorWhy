# 暗规则库 · 器械 UI 规范(Device UI)

> 医疗器械/临床环境特有的 UI 约束。通用 AI 不知道这些,会把医疗 UI 做成普通网页。
> 每条 = 规则 + 为什么问(医学现实)+ 踩过什么坑(真实事故)。
> 审查 UI 时逐条过;追问时按需带出。

---

## 1. 高对比 + 深色界面优先

- **规则**:临床环境优先深色背景 + 高对比文字(浅色文字 #fff 于深底 #1b2433)。浅色主题需保证对比度 ≥ 4.5:1。
- **为什么问**:病理/检验科常是暗室(看显微镜、荧光),普通网页的亮白底在暗室刺眼;反之强光下浅灰字看不清。设备常隔一段距离摆放,深底白字最稳。
- **踩坑**:白底 + 浅灰占位符,在暗室里整屏发白、输入框看不清;或浅色主题对比度不足,日光下没法读。

## 2. 警示不能只靠颜色(颜色 + 图标 + 文字三重)

- **规则**:任何"危险/警告/成功"状态,必须颜色 + 图标 + 文字同时表达。禁止只用红绿区分。
- **为什么问**:红绿色盲约占人口 8%(男性更高),而红绿恰是医疗警示常用色。只靠红绿,色盲操作员会把"危险"当"正常"。
- **踩坑**:扫描失败用红色×、成功用绿色✓,色盲用户看两者几乎一样;或错误提示只是红字没有文字说明。

## 3. 大字号 + 隔距读屏

- **规则**:正文 ≥ 16px,关键信息(状态/警告/读数)≥ 18-20px。操作员可能站立、隔 0.5-1m 看屏。
- **为什么问**:技师/医生不是凑在屏幕前看邮件,是站着操作设备、隔一段距离确认状态。
- **踩坑**:按网页标准做 14px,隔 1m 完全看不清扫描状态和玻片编号。

## 4. 防误操作:危险动作二次确认

- **规则**:不可逆动作(删除记录、覆盖数据、提交诊断、发报告、开始耗时的扫描)必须二次确认;能撤销的给撤销。
- **为什么问**:医疗数据不可逆,误点一次 = 病历丢失/误报报告。操作员长时间重复操作,容易肌肉记忆误触。
- **踩坑**:删除玻片记录没有确认框,误触后数据直接没;或"确认"按钮和"取消"摆太近。

## 5. 数据密集布局:对齐 + 单位统一 + 可快扫

- **规则**:数字列右对齐、小数点对齐;单位统一并在表头标注;同一指标全系统用同一单位。检验单要"扫一眼读出结论"。
- **为什么问**:检验单/病历是数字海洋,医生靠扫读定位异常值。单位混用(mg/mL vs mg/dL)会直接误判数值。
- **踩坑**:血细胞计数列左对齐,数字位数不同导致对不齐难扫读;或一处显示 %、一处显示比例,医生比对出错。

## 6. 状态一眼可辨识,靠多通道不靠细微色差

- **规则**:设备/扫描状态(空闲/运行/待选区/异常/完成)要有独立的状态区,用颜色 + 标签文字 + 位置共同表达,状态间对比度足够。
- **为什么问**:操作员同时盯多台设备,要瞬间判断每台在干嘛,不能点进去才知道。
- **踩坑**:待选区用浅绿、完成用深绿,光线一差两者分不清;或状态只是角落一个小色点。

## 7. 错误/异常提示要醒目、可行动

- **规则**:异常弹窗要显眼(模态或常驻),写明"出了什么事 + 操作员该怎么做",不能只报个错误码。
- **为什么问**:设备故障/扫描失败时,操作员要立刻知道严重性和下一步。含糊提示会让人反复重启或漏报。
- **踩坑**:"操作失败"四个字没有任何原因和指引;或错误只出现在日志里,界面看不到。

## 8. 触控/触摸友好尺寸

- **规则**:可点击目标 ≥ 44×44px,间距足够;考虑戴手套操作。
- **为什么问**:临床设备大量触屏,技师可能戴手套、手指粗糙或湿,网页式小按钮点不准。
- **踩坑**:登录/选区按钮做成 32px 高,戴手套点好几次才点上;相邻按钮太近误触。

## 9. 克制装饰:无花哨动画、无渐变炫技

- **规则**:UI 聚焦信息传达,不用装饰性动画、渐变、弹跳、微动效;动画只能用于表示"正在加载/进度"。
- **为什么问**:临床是高注意力场景,装饰动效增加认知负担、分散对状态的注意。
- **踩坑**:登录成功弹个动画庆祝,扫描界面用渐变按钮 —— 干扰操作员判断真实状态。

## 10. 长任务必须有明确进度,禁止无限转圈

- **规则**:扫描/分析/导入等长任务,显示进度(百分比/已处理数/阶段名),且可取消或暂停;禁止无限转圈。
- **为什么问**:扫描一片玻片要几十分钟,操作员要知道"进行到哪、还差多久",否则会误判卡死而强行重启(丢数据)。
- **踩坑**:扫描过程只有一个转圈,操作员以为卡住就重启,已扫的数据丢失。

## 11. 文案克制:朴素业务词,禁互联网腔

- **规则**:界面文案用朴素业务词("当日病历""报告预览""保存""审核并打印"),**禁止**互联网/产品化腔("总览""洞察""智能分析""概览"),按钮动宾明确,不用浮夸副词。
- **为什么问**:医疗软件使用者是医生/技师,要的是直接、专业、无歧义。"当日病历总览"这种 AI 味/数据看板词,临床用户会觉得不专业甚至看不懂。
- **踩坑**:侧栏标题"当日病历总览"被医生指出"有 AI 味";按钮写"开启智能分析之旅"而非"开始分析"。

---

## 这些规则能点破什么矛盾(供"点破隐含矛盾"动作使用)

- 用户说"登录界面做漂亮点" → 点破"消费级美观" 与 "临床可读/克制" 的矛盾:亮白渐变好看,但暗室刺眼。
- 用户说"扫描失败弹窗别太吓人" → 点破"低调提示" 与 "必须可行动" 的矛盾:医疗异常必须醒目,否则漏报。
- 用户说"按钮做小一点省空间" → 点破"省空间" 与 "触控/防误触" 的矛盾:设备触屏必须大。
- 用户说"标题写'当日病历总览'更有产品感" → 点破"产品感" 与 "临床朴素文案" 的矛盾:医疗用户要的是直接,不是包装。
